# Bilingual Documentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve the complete English guide at the GitHub Pages root and the complete Korean guide at `/ko/`, with a visible language switch and shared assets.

**Architecture:** Keep the site build-free by committing two static HTML entry points. `docs/index.html` is English, `docs/ko/index.html` is Korean, and both use the existing shared stylesheet and script. Runtime messages live in each page's `body` data attributes so the shared JavaScript contains no language-specific branching.

**Tech Stack:** HTML5, CSS, browser JavaScript, Node.js built-in modules for validation, GitHub Pages branch deployment.

**Spec:** `design/2026-08-16-docs-i18n-design.md`

## Global Constraints

- English is served at `/sampler-tui/`; Korean is served at `/sampler-tui/ko/`.
- Do not redirect based on browser language.
- Keep identical section IDs in both languages.
- Use only relative asset paths that work under the `/sampler-tui/` project path.
- Keep the existing flat, non-glowing instrument-panel visual treatment.
- Do not add a translation framework, build system, or Pages workflow.
- Do not stage or track `.superpowers`, `.codex`, or `.agents`.

### Task 1: Add the bilingual Pages contract validator

**Files:**
- Create: `scripts/verify-docs-i18n.mjs`
- Test: `scripts/verify-docs-i18n.mjs`

**Interfaces:**
- Consumes: `docs/index.html`, `docs/ko/index.html`, `docs/styles.css`, and `docs/app.js` from the repository root.
- Produces: a zero exit code and `docs i18n contract: OK` when both localized routes satisfy the Pages contract; throws an assertion error otherwise.

- [ ] **Step 1: Write the failing validator**

Create a dependency-free Node script using `node:assert/strict`, `node:fs`, and `node:path`. It must read both localized pages and assert these literal expectations:

```js
assert.equal(tagAttribute(english, "html", "lang"), "en");
assert.equal(tagAttribute(korean, "html", "lang"), "ko");
assert.deepEqual(sectionIds(english), sectionIds(korean));
assert.equal(unresolvedAnchors(english).length, 0);
assert.equal(unresolvedAnchors(korean).length, 0);
assert.match(english, /href="\.\/ko\/"/);
assert.match(korean, /href="\.\.\/"/);
assert.match(english, /href="\.\/styles\.css"/);
assert.match(english, /src="\.\/app\.js"/);
assert.match(korean, /href="\.\.\/styles\.css"/);
assert.match(korean, /src="\.\.\/app\.js"/);
assertCanonical(english, "https://bonzonkim.github.io/sampler-tui/");
assertCanonical(korean, "https://bonzonkim.github.io/sampler-tui/ko/");
assertAlternateLanguages(english, ["en", "ko", "x-default"]);
assertAlternateLanguages(korean, ["en", "ko", "x-default"]);
assertRuntimeStrings(english, "en");
assertRuntimeStrings(korean, "ko");
assertNoRootRelativeAssets(english);
assertNoRootRelativeAssets(korean);
console.log("docs i18n contract: OK");
```

The helper functions must parse opening tags and attributes with focused regular expressions, return section IDs in document order, compare every `href="#..."` with the page's ID set, and verify that every runtime string attribute is present and non-empty.

- [ ] **Step 2: Run the validator and verify RED**

Run:

```sh
node scripts/verify-docs-i18n.mjs
```

Expected: FAIL because `docs/ko/index.html` does not exist and the current root page has `lang="ko"`.

- [ ] **Step 3: Commit the failing contract**

```sh
git add scripts/verify-docs-i18n.mjs
git commit -m "test: define bilingual docs contract"
```

### Task 2: Create the English root and Korean route

**Files:**
- Modify: `docs/index.html`
- Create: `docs/ko/index.html`
- Modify: `docs/styles.css`

**Interfaces:**
- Consumes: the route and metadata expectations in `scripts/verify-docs-i18n.mjs`.
- Produces: English and Korean HTML pages with identical section IDs and reciprocal `.language-switch` links.

- [ ] **Step 1: Preserve the Korean guide at `/ko/`**

Copy the current `docs/index.html` content to `docs/ko/index.html`, then make these path and metadata changes:

```html
<html lang="ko" data-theme="dark">
<link rel="canonical" href="https://bonzonkim.github.io/sampler-tui/ko/">
<link rel="alternate" hreflang="en" href="https://bonzonkim.github.io/sampler-tui/">
<link rel="alternate" hreflang="ko" href="https://bonzonkim.github.io/sampler-tui/ko/">
<link rel="alternate" hreflang="x-default" href="https://bonzonkim.github.io/sampler-tui/">
<link rel="stylesheet" href="../styles.css">
<script src="../app.js" defer></script>
```

Add the language control inside `.top-actions`:

```html
<nav class="language-switch" aria-label="언어 선택">
  <a href="../" lang="en" hreflang="en">EN</a>
  <a href="./" lang="ko" hreflang="ko" aria-current="page">KO</a>
</nav>
```

- [ ] **Step 2: Translate the root page completely into English**

Keep all IDs, classes, commands, key names, and keyboard layouts unchanged. Translate metadata, navigation, headings, paragraphs, callouts, tables, FAQ content, labels, buttons, accessibility text, and search UI. Set these route elements:

```html
<html lang="en" data-theme="dark">
<link rel="canonical" href="https://bonzonkim.github.io/sampler-tui/">
<link rel="alternate" hreflang="en" href="https://bonzonkim.github.io/sampler-tui/">
<link rel="alternate" hreflang="ko" href="https://bonzonkim.github.io/sampler-tui/ko/">
<link rel="alternate" hreflang="x-default" href="https://bonzonkim.github.io/sampler-tui/">
```

Add the reciprocal control:

```html
<nav class="language-switch" aria-label="Choose language">
  <a href="./" lang="en" hreflang="en" aria-current="page">EN</a>
  <a href="./ko/" lang="ko" hreflang="ko">KO</a>
</nav>
```

- [ ] **Step 3: Style the language control**

Add `.language-switch` beside the existing top actions. Use a one-pixel border, two compact monospace links, square corners, no glow, and a flat filled state for `[aria-current="page"]`. At the 760px breakpoint, retain both `EN` and `KO` labels while the GitHub label remains hidden.

- [ ] **Step 4: Run the validator and inspect the expected remaining failure**

Run:

```sh

```

Expected: FAIL only on missing per-page runtime string attributes; route, metadata, anchor, section, and asset assertions pass.

- [ ] **Step 5: Commit the localized routes**


### Task 3: Localize shared runtime messages

**Files:**
- Modify: `docs/index.html`
- Modify: `docs/ko/index.html`
- Modify: `docs/app.js`
- Test: `scripts/verify-docs-i18n.mjs`

**Interfaces:**
- Consumes: `body.dataset.themeLightLabel`, `themeDarkLabel`, `searchEmptyTemplate`, and `copySuccess` from each page.
- Produces: localized theme labels, search empty state, and clipboard feedback without language-specific branches in shared JavaScript.

- [ ] **Step 1: Add literal runtime messages to each page**

English body attributes:

```html
<body id="top"
  data-theme-light-label="Switch to light theme"
  data-theme-dark-label="Switch to dark theme"
  data-search-empty-template="No documentation found for “{query}”."
  data-copy-success="Copied to clipboard">
```

Korean body attributes:

```html
<body id="top"
  data-theme-light-label="밝은 테마로 전환"
  data-theme-dark-label="어두운 테마로 전환"
  data-search-empty-template="“{query}”에 맞는 문서가 없습니다."
  data-copy-success="클립보드에 복사했습니다">
```

- [ ] **Step 2: Make shared JavaScript consume the page strings**

Define one immutable object after `const body = document.body`:

```js
const uiStrings = Object.freeze({
  themeLightLabel: body.dataset.themeLightLabel,
  themeDarkLabel: body.dataset.themeDarkLabel,
  searchEmptyTemplate: body.dataset.searchEmptyTemplate,
  copySuccess: body.dataset.copySuccess,
});
```

Replace the hard-coded Korean values in `setTheme`, `renderSearch`, and `copyText` with these fields. Build the empty-state message using:

```js
empty.textContent = uiStrings.searchEmptyTemplate.replace("{query}", cleanQuery);
```

Run:

Expected: both commands exit 0; the validator prints `docs i18n contract: OK`.
